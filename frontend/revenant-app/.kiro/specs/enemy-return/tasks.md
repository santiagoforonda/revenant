# Enemy Return - Tasks Document

## Overview

This document defines the implementation tasks for the Enemy Return feature.

The objective is to implement a dedicated return system that moves enemies back to their original spawn position after the player is no longer detected.

This feature completes the passive enemy AI cycle by transferring control from Enemy Chase back to Enemy Patrol.

# Implementation Plan

## Phase 1 - Return Infrastructure

**Objectives**

- Introduce the Return Controller.
- Integrate the return update cycle.
- Preserve each enemy's spawn position.

**Deliverables**

- Return Controller.
- Spawn position management.
- MainScene integration.

---

## Phase 2 - Return Movement

**Objectives**

- Implement movement toward the original spawn position.
- Update movement state and facing direction.

**Deliverables**

- Continuous return movement.
- Direction calculation.
- Return speed management.

---

## Phase 3 - AI Integration

**Objectives**

- Integrate Return with Chase and Patrol.
- Synchronize movement with the Enemy Animation module.

**Deliverables**

- Chase-to-Return transition.
- Return-to-Patrol transition.
- Animation synchronization.

---

## Phase 4 - Validation

**Objectives**

- Validate return behavior.
- Verify architectural compliance.

**Deliverables**

- Stable Enemy Return system.
- Successful integration with the existing AI architecture.

## Tasks

- [x] 1. Implement the Return Controller.

  - Create the Return Controller component.
  - Maintain the current return state.
  - Store the return target using the enemy's original spawn position.
  - Initialize the return process only after receiving Chase Controller notifications.

---

- [x] 2. Integrate the return update cycle.

  - Create one Return Controller for every spawned enemy.
  - Update every Return Controller during the MainScene update loop.
  - Ensure each enemy returns independently.
  - Keep MainScene responsible only for invoking controller updates.

---

- [x] 3. Preserve enemy spawn positions.

  - Store the original spawn position when each enemy is created.
  - Keep the stored spawn position immutable during gameplay.
  - Expose the spawn position to the Return Controller.
  - Validate that every enemy has a valid return target.

---

- [x] 4. Implement return movement.

  - Move the enemy toward its stored spawn position.
  - Calculate a normalized movement vector.
  - Apply the configured return speed.
  - Stop movement immediately after reaching the destination.

---

- [x] 5. Integrate with Enemy Chase.

  - Start the Return Controller after the Chase Controller reports PlayerLost.
  - Prevent Chase and Return from running simultaneously.
  - Prevent duplicate return state transitions.
  - Keep Chase Controller responsible only for pursuit.

---

- [x] 6. Integrate with Enemy Patrol and Animation.

  - Resume the Patrol Controller after the return process completes.
  - Switch the enemy to the Walking state while returning.
  - Switch the enemy to the Idle state upon arrival.
  - Reuse the existing Enemy Animation infrastructure without duplicating animation logic.

---

- [x] 7. Validate return behavior.

  - Verify enemies begin returning immediately after chase ends.
  - Verify enemies always return to their original spawn position.
  - Verify patrol resumes automatically after arrival.
  - Verify multiple enemies return independently.
  - Verify movement remains smooth throughout the return process.

---

- [x] 8. Validate architecture compliance.

  - Verify Return Controller never performs player detection.
  - Verify Return Controller never initiates combat.
  - Verify MainScene contains no return logic.
  - Verify Enemy Return remains reusable by future Combat modules.
  - Verify the feature remains independent from backend communication, pathfinding, damage calculation, and attack logic.

---

## Notes

- This feature MUST comply with:
  - `phaser_developer.md`
  - `react_developer.md`

- This feature MUST comply with the architecture documentation located under:

  ```text
  docs/architecture/
  ```

- Return behavior MUST be implemented through a dedicated `ReturnController`.

- Each enemy MUST preserve its original spawn position for the entire game session.

- Enemy Return MUST only react to notifications generated by the `ChaseController`.

- The Return Controller MUST always move enemies toward their stored spawn position.

- Patrol MUST automatically resume after the enemy reaches its destination.

- Enemy Animation MUST continue to manage all animation playback.

- Enemy Return MUST never invoke Phaser animations directly.

- MainScene MUST only update Return Controllers and MUST NOT contain return logic.

- Enemy Return MUST remain reusable by future modules including:
  - Enemy Combat

- Out of scope:
  - Player detection.
  - Enemy patrol logic.
  - Enemy chase logic.
  - Combat.
  - Damage.
  - Attack logic.
  - Attack animations.
  - Death handling.
  - Loot.
  - Rewards.
  - Pathfinding.
  - Backend communication.
