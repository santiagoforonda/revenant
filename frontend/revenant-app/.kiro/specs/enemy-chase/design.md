# Enemy Chase - Design Document

## Overview

This document describes the design of the Enemy Chase feature.

The purpose of this feature is to allow enemies to actively pursue the player after being notified by the Enemy Detection module.

Enemy Chase is responsible exclusively for movement toward the player's current position. It continuously updates the chase target while the player remains detected.

This feature extends the Enemy Detection module and serves as the bridge between passive AI and future combat behavior.

Enemy Chase does not implement combat, attack logic, damage, pathfinding, or return-to-patrol behavior.

---

## Architecture

Enemy Chase introduces a dedicated Chase Controller responsible for controlling enemy pursuit.

The Chase Controller listens for detection state changes generated by the Detection Controller. Once the player has been detected, it continuously calculates the movement direction toward the player's current position and updates the enemy accordingly.

Enemy Chase does not decide when the player has been detected, nor does it decide when combat begins. It only controls pursuit.

### High-Level Architecture

```text
             Detection Controller
                      │
          PlayerDetected / PlayerLost
                      │
                      ▼
              Chase Controller
                      │
       ┌──────────────┴──────────────┐
       ▼                             ▼
 Target Position              Movement Update
       │                             │
       └──────────────┬──────────────┘
                      ▼
              Enemy Position
                      │
                      ▼
          Enemy State / Direction
                      │
                      ▼
          Enemy Animation Module
                      │
                      ▼
           EnemySpriteComposer
                      │
                      ▼
       EnemyAnimationController
                      │
                      ▼
        Phaser Animation Manager
```

The Chase Controller is responsible only for pursuit.

Enemy Animation remains responsible for animation playback.

Future AI modules such as Combat and Return will subscribe to Chase state changes without modifying the Chase Controller.

## Components and Interfaces

### Enemy

**Responsibilities**

- Store the current world position.
- Store the current movement state.
- Store the current facing direction.
- Expose movement operations.
- Expose the current Chase state.

Enemy must not calculate pursuit logic.

---

### Player

**Responsibilities**

- Expose its current world position.
- Update its position through the existing movement system.

The Player remains completely unaware of Enemy Chase.

---

### Chase Controller

**Responsibilities**

- Listen for detection state changes.
- Start pursuit when the player is detected.
- Stop pursuit when detection is lost.
- Continuously calculate movement toward the player.
- Update enemy movement state.
- Update enemy facing direction.

The Chase Controller contains all pursuit logic.

---

### Detection Controller

**Responsibilities**

- Notify when the player is detected.
- Notify when detection is lost.

Detection remains the only component responsible for deciding whether pursuit should begin.

---

### Enemy Animation Module

**Responsibilities**

- Receive movement state updates.
- Receive direction updates.
- Play Walking animations.
- Play Idle animations.

Enemy Chase never invokes Phaser animations directly.

---

### MainScene

**Responsibilities**

- Update every Chase Controller during the game loop.
- Provide references to the player and enemy.

MainScene must never contain chase logic.

---

## Data Models

### Chase State

Supported values:

```text
Inactive

Chasing
```

The Chase Controller transitions between these states according to Detection Controller notifications.

---

### Chase Target

Represents the player's current world position.

```text
targetX

targetY
```

The chase target is updated continuously while the player remains detected.

---

### Chase Speed

Represents the enemy movement speed while pursuing the player.

```text
chaseSpeed
```

The chase speed is configurable independently from patrol speed.

---

## Correctness Properties

The following invariants must always hold:

- Enemy Chase must begin only after Detection Controller reports player detection.
- Enemy Chase must stop immediately after Detection Controller reports detection loss.
- Chase calculations must always use the player's current position.
- Enemy direction must always reflect movement direction.
- Enemy state transitions must remain synchronized with the Enemy Animation module.
- Enemy Chase must never invoke Phaser animations directly.
- Enemy Chase must never determine detection state.
- Enemy Chase must never communicate with the backend.
- Enemy Chase must remain independent from Enemy Patrol.
- Enemy Chase must remain independent from Enemy Combat.
- Chase logic must remain reusable by future AI modules.

---

## Error Handling

The system shall gracefully handle the following situations:

- Missing player reference.
- Missing enemy reference.
- Invalid chase target.
- Invalid movement state.
- Unexpected pursuit failures.

Whenever pursuit cannot continue safely, the enemy shall stop moving and leave the Chase state.

The scene must never terminate because of chase failures.

---

## Testing Strategy

### Unit Testing

Verify that:

- Chase begins after player detection.
- Chase stops after detection loss.
- Movement direction is calculated correctly.
- Enemy direction updates correctly.
- Invalid targets are handled safely.
- Missing references are handled correctly.

---

### Integration Testing

Verify that:

- Detection Controller successfully activates the Chase Controller.
- Chasing enemies continuously follow the player's position.
- Enemy direction updates correctly while chasing.
- Walking animations remain synchronized with pursuit.
- Multiple enemies chase the player independently.
- Chase stops immediately after detection loss.

---

### End-to-End Testing

Verify that:

- Patrolling enemies begin chasing after detecting the player.
- Chasing enemies continuously pursue the moving player.
- Chase updates correctly while the player changes direction.
- Chase stops immediately after the player leaves the detection radius.
- Enemy animations remain synchronized throughout pursuit.
- Multiple enemies chase the player simultaneously.
- Enemy Chase remains independent from Patrol, Combat, Return, backend communication, and pathfinding.
