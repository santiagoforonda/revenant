# Enemy Chase - Tasks Document

## Overview

This document defines the implementation tasks for the Enemy Chase feature.

The objective is to implement an autonomous pursuit system that moves enemies toward the detected player while the Detection Controller reports an active detection state.

This feature extends the Enemy Detection module without introducing combat, attacks, pathfinding, or return-to-patrol behavior.

## Tasks

- [x] 1. Implement the Chase Controller.

  - Create the Chase Controller component.
  - Maintain the current chase state.
  - Store the chase target.
  - Initialize pursuit only after receiving Detection Controller notifications.

---

- [x] 2. Integrate the chase update cycle.

  - Create one Chase Controller for every spawned enemy.
  - Update every Chase Controller during the MainScene update loop.
  - Ensure each enemy performs pursuit independently.
  - Keep MainScene responsible only for invoking controller updates.

---

- [x] 3. Implement player pursuit.

  - Move the enemy toward the player's current position.
  - Continuously update the chase target.
  - Stop movement when pursuit is inactive.
  - Support simultaneous pursuit for multiple enemies.

---

- [x] 4. Implement chase movement calculations.

  - Calculate the normalized movement vector toward the player.
  - Apply the configured chase speed.
  - Update the enemy position continuously.
  - Handle invalid chase targets safely.

---

- [x] 5. Integrate with Enemy Detection.

  - Start pursuit when Detection Controller reports PlayerDetected.
  - Stop pursuit when Detection Controller reports PlayerLost.
  - Prevent duplicate chase state transitions.
  - Keep Detection Controller responsible only for detection events.

---

- [x] 6. Synchronize with Enemy Animation.

  - Switch enemies to the Walking state while chasing.
  - Switch enemies to the Idle state when pursuit ends.
  - Update facing direction during movement.
  - Reuse the existing Enemy Animation infrastructure without duplicating animation logic.

---

- [x] 7. Validate chase behavior.

  - Verify enemies begin chasing immediately after player detection.
  - Verify pursuit continuously follows the player's current position.
  - Verify pursuit stops immediately after detection loss.
  - Verify multiple enemies chase the player independently.
  - Verify movement remains smooth during continuous player movement.

---

- [x] 8. Validate architecture compliance.

  - Verify Chase Controller never performs player detection.
  - Verify Chase Controller never starts combat.
  - Verify MainScene contains no chase logic.
  - Verify Enemy Chase remains reusable by future Return and Combat modules.
  - Verify the feature remains independent from backend communication, pathfinding, attack logic, and reward systems.

---

## Notes

- This feature MUST comply with:
  - `phaser_developer.md`
  - `react_developer.md`

- This feature MUST comply with the architecture documentation located under:

  ```text
  docs/architecture/
  ```

- Chase behavior MUST be implemented through a dedicated `ChaseController`.

- Enemy Chase MUST only react to notifications generated by the `DetectionController`.

- The player's current position MUST be recalculated every update cycle while chasing.

- Enemy Animation MUST continue to manage all animation playback.

- Enemy Chase MUST never invoke Phaser animations directly.

- MainScene MUST only update Chase Controllers and MUST NOT contain chase logic.

- Enemy Chase MUST remain reusable by future modules including:
  - Enemy Return
  - Enemy Combat

- Out of scope:
  - Player detection.
  - Enemy patrol.
  - Enemy return.
  - Combat.
  - Damage.
  - Attack logic.
  - Attack animations.
  - Death handling.
  - Loot.
  - Rewards.
  - Pathfinding.
  - Backend communication.
