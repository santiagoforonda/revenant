# Combat System - Tasks Document

## Overview

This implementation introduces the Combat System for the Revenant game.

The Combat System is responsible for resolving every `AttackRequest` generated by the Player Attack feature. It calculates damage, applies armor reduction, updates enemy health, detects defeated enemies, and publishes combat events.

Combat resolution is performed entirely on the client.

No backend communication is performed during combat. Backend persistence is delegated to the Reward System after an enemy has been defeated.

## Tasks

- [x] 1. Implement the combat domain models.
  - Create the `CombatResult` model.
  - Define the combat result properties.
  - Create the combat event models.
  - Ensure the models are immutable where appropriate.

---

- [x] 2. Implement the DamageCalculator.
  - Create the `DamageCalculator` service.
  - Calculate damage using attacker attack and target armor.
  - Prevent negative damage values.
  - Return the calculated combat damage.

---

- [x] 3. Implement the CombatSystem.
  - Subscribe to `AttackRequest` events from the Event Bus.
  - Process every target contained in the request.
  - Coordinate the combat resolution workflow.
  - Resolve every target independently.

---

- [x] 4. Apply combat resolution.
  - Apply calculated damage to every target.
  - Update enemy health.
  - Detect defeated enemies.
  - Prevent additional damage to defeated enemies.
  - Generate a `CombatResult` for every processed target.

---

- [x] 5. Publish combat events.
  - Publish a `CombatResolvedEvent` after resolving each target.
  - Publish an `EnemyDefeatedEvent` when an enemy dies.
  - Ensure only one defeat event is emitted per enemy.
  - Integrate the events with the Event Bus.

---

- [x] 6. Support multiple targets.
  - Resolve every enemy contained in the `AttackRequest`.
  - Continue processing remaining targets if one enemy is defeated.
  - Complete combat resolution even when no targets are present.
  - Ensure combat results remain independent for every target.

---

- [x] 7. Implement error handling.
  - Handle empty `AttackRequest` objects.
  - Handle invalid or unavailable targets.
  - Handle already defeated enemies.
  - Handle damage calculation failures.
  - Log recoverable errors without interrupting gameplay.

---

- [x] 8. Implement automated tests.
  - Create unit tests for `DamageCalculator`.
  - Create unit tests for `CombatSystem`.
  - Create unit tests for enemy health updates.
  - Create unit tests for enemy death detection.
  - Create unit tests for combat event publication.
  - Create integration tests for the complete combat resolution workflow.
  - Verify that no backend communication occurs during combat.

## Notes

- This feature must comply with:
  - `phaser_developer.md`
  - `react_developer.md`
  - `docs/game-directory-structure.md`
  - `docs/react-phaser-architecture.md`
  - `docs/react-phaser-events.md`

- The Combat System must subscribe to `AttackRequest` events published by the Player Attack feature.

- Combat resolution must execute entirely on the client.

- The Combat System must never perform HTTP requests.

- Every `AttackRequest` must be processed exactly once.

- Every target inside an `AttackRequest` must be resolved independently.

- Every processed target must generate a `CombatResolvedEvent`.

- Every defeated enemy must generate exactly one `EnemyDefeatedEvent`.

- Backend communication is **strictly prohibited** during combat resolution.

- Backend persistence is performed exclusively by the Reward System after an enemy has been defeated.

- The Combat System must remain independent from player input, attack animations, rewards, inventory, quests, stores, and enemy AI.
